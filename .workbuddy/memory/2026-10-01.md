## 代码改动
- BoxingBuddy：rig + 3 动画 Promise.all 并行；兜底贴图仅在检测到内嵌贴图失败后才拉取；眨眼贴图 ready 后才懒加载；URL 加 `?v=2`
- BoxingBoy3D：onLoad 改 async，兜底贴图**应用完成后**才 setReady → 灰模窗口被 loading 条盖住
- 首页路由 `links` 导出 `<link rel="preload" as="fetch" crossorigin="anonymous">` 预加载 hero GLB（必须带 crossorigin，否则 preload 和 fetch 不匹配会下载两次）

## 重要环境教训：headless 测试浏览器的假信号
- agent-browser（Playwright Chromium）里 **`fetch()` 对任何 blob: URL 都失败**（连纯文本 blob 都 "Failed to fetch"），但 `createImageBitmap(blob)` 正常 → GLTFLoader 的 ImageBitmapLoader 走 fetch 必挂 → **所有内嵌贴图报 "Couldn't load texture blob"**
- 因此在 headless 里看到的"内嵌贴图失败→兜底加载"**不能代表真实浏览器**；诊断时要先用 `fetch(URL.createObjectURL(new Blob(['hi'])))` 验证环境本身
- 另外：`sips` 不支持输出 webp；Pillow（venv 里有 12.3.0）或 sharp（gltf-transform 依赖）可用
- gltf-transform `quantize` 会打日志 "prune: Removed types... Skin (1)" 但**蒙皮实际完好**（skins=1/joints=33），要以 JSON 校验为准，别被日志吓到
- 疑似回归时先排除"自转模型截图角度不同"这类假差异：连拍多张再下结论

## 拳击小子贴角调整（commit 6329506，本地已提交，push 待用户执行）
- 问题：右下角 mascot 距右边缘/底部空隙过大，移动端尤其明显。
- 根因：canvas 相机按 bbox 居中取景 → 画布约 40% 宽度是透明死区（桌面右侧 60px + CSS 16px = 76px；移动端 39px + 8px = 47px）。
- 修法（纯 CSS）：`.boxing-buddy` 整体负偏移让角色贴角、多余透明画布悬出屏外（fixed 元素不产生滚动条）：desktop `right: calc(1rem - 66px); bottom: -9px`；mobile `right: calc(0.5rem - 39px); bottom: -5px`。
- 测量验证（隐藏 main/header/footer + 洋红背景 + PIL 像素 bbox）：右侧 76→9px（桌面）/ 47→7px（移动），底部 15→6px / 10→5px；点击 punch 正常；scrollWidth==innerWidth 无横向滚动。
- 测量小技巧：agent-browser eval 把页面内容 visibility:hidden + 纯色背景，截图后用 numpy 找非背景像素 bbox，比目测截图准。
